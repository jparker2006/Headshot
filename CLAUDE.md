# Headshot

The shared brain of who was in what with whom. Read `SPEC.md` first; it is the source of truth for every product and architecture decision and was confirmed line by line.

## Layout
- `scripts/build-graph/` — offline pipeline: IMDb TSVs → filtered, tiered, packed adjacency arrays → Vercel Blob (versioned). Runs on a Mac with `pnpm build:graph`. `--tmdb` adds the second stage: TMDB full casts for the top titles, cached under `data/tmdb/`, packed as weak edges plus a character table (format v2; the loader still reads v1).
- `scripts/embed/` — `pnpm embed` embeds the top entities into the brain's pgvector table for the semantic fallback in `find_entities` / `find_by_constraints`.
- `src/lib/graph/` — the in-process industry graph: binary loader, tiered bidirectional BFS, tied-path enumeration, overlay merge. Deterministic, no network, no model. Primary test seam.
- `src/lib/brain/` — Postgres (Neon + pgvector, Drizzle) for the shared brain: touched nodes, overlay edges, wiki pages, revision log, embeddings, session glow.
- `src/lib/tmdb/` — TMDB client (pattern copied from Cinema Daddy, no UI copied).
- `src/lib/agent/` — AI SDK agent loop on OpenRouter; tools under `tools/`. `shortest_path` results pass through unmodified; the agent never invents a path. v2: `fastpath.ts` classifies a question (path / costar / both / known-for / identify) and computes the deterministic result before the model; `answers.ts` keys stored answers by shape + sorted ids and replays hits with no model call; `identify.ts` solves "who is that guy from that show" over full casts. v5: the taste tool set is `log`, `my_profile`, `recall`, `have_i_seen`, `tonight` (the pick engine on demand), plus the trivia tools.
- `src/lib/answers/` — permalinks `/a/<slug>-<shortid>` for public stored answers and their Open Graph images.
- v3 (Tonight): `src/lib/auth/` — Neon Managed Better Auth, magic link only, opt-in (nothing redirects; protected routes answer 401); `createAccountHandlers` behind `DELETE /api/me` deletes every private row then the auth account (Better Auth's `deleteUser`; when the project has user deletion off the call is refused, the session is revoked instead and the auth row remains — the response says which in `account`). `src/lib/taste/` — the private per-user store (watched / services / taste / memory / episodes / crawls tables on the same Postgres, Memory + Postgres implementations, one conformance suite), the CSV imports, `letterboxdCrawl.ts` (the public films / watchlist / diary pages, sequential and 300ms apart with a real UA, matched through the CSV import's own matcher, written with `replaceImport`, cached 24h per user in `crawls`; `POST|GET /api/taste/import/letterboxd`), providers list. `src/lib/threads/` — server-side chat threads (`ThreadStore`, Memory + Postgres, one conformance suite; `/api/threads`). `src/lib/picks/` — the pick engine (pure; the graph-reason rule lives in `graphReason`), candidate pool (graph walk + TMDB discover), `pickNow` (Tonight computed on demand: no cron, no stored row), swipe reducer, onboarding deck. `src/app/settings`, `src/app/welcome/*` and `src/app/auth/sign-in` are the only signed-in pages.
- `src/app/api/chat/` — streaming route; emits typed data parts the canvas animates.
- `src/components/canvas|chat|page/` — sigma.js brain canvas, floating chat panel, wiki page side panel.
- `tests/` — vitest, fixture-driven. Seams (highest first): graph engine (incl. constraint solving and characters), pipeline (incl. the TMDB stage over `tests/fixtures/tmdb`), agent loop with mocked model (fast path, cache replay, thread persistence, face grid), route (permalinks, OG image, rate-limit cap), client rules (entity links, face-grid tap).

## Rules
- Two graphs, never confused: the precomputed industry graph (read-only, in memory) and the brain (shared, mutable, in Postgres). The canvas renders the brain only.
- Bacon number is computed, never estimated. Strong tier first, full graph fallback, report both when they differ.
- One provider: OpenRouter. Model IDs live in env vars, never in code.
- The shared brain has no auth and no per-user state. Signed-in conversations are stored per user in `threads`/`messages` (one row per UI message, every method scoped by user id); signed-out ones stay in localStorage and are never sent. Accounts exist only for the v3 taste graph and the v5 threads, and every private row carries a user id. Signed-out Headshot must keep working in full.
- Every pick carries exactly one reason and it must be a real graph fact (`graphReason`); no reason, no pick. Taste signals are explicit only (swipe, import, chat); nothing is inferred from clicks.
- Fresh UI. Do not copy Cinema Daddy styling. Tailwind v4 with a hand-written token layer.
- Node.js runtime (Fluid Compute). Never `runtime = 'edge'`.
- Run `pnpm typecheck && pnpm lint && pnpm test` before claiming anything works.
- Keyless dev: `HEADSHOT_GRAPH_PATH=data/fixture.bin` + `HEADSHOT_MOCK_AGENT=1` in `.env.local` runs the fixture graph with the scripted model in `src/lib/agent/mockModel.ts`. `window.__headshot` exposes sigma and the store in dev for QA. `HEADSHOT_DEV_USER=<id>` signs every request in as that id outside production, so Tonight and the taste routes can be exercised without the magic-link email loop.
- The model is told to wrap every entity name in `**bold**`; the client resolves those against the message's `data-node` parts and renders links that open the drawer ("cursor for movies"). Keep that rule in the system prompt.
- Thread views are `noindex`; only `/a/...` answer pages are indexable.
- Brain tests run against embedded Postgres (PGlite + pgvector) and the memory brain through one shared conformance suite in `tests/brain`.
- v5.3 (in progress, see SPEC.md "# v5.3 — Memory you can read"): the memory is **claims with evidence**, not prose. `memory.claims` (jsonb, migration 0010) holds `{ sentence, claims: [{ id, text, evidence: imdbIds, polarity: "love" | "avoid" }], rejected: [{ text }] }`; the rewrite model returns JSON and nothing it says is trusted — `validateClaims` (`src/lib/memory/claims.ts`, pure) drops evidence that is not a current row or a known person id, drops evidence whose score disagrees with the polarity (`backs`: love needs a score ≥7 or a person, avoid needs a score <7, an unscored row backs nothing), drops a claim left with no evidence, caps at 8 claims / 2 avoids / 12-word text / 20-word sentence, strips `**`, never lets a rejected text back (case-insensitive substring, either direction), and reuses the previous claim's id when the text matches. `markdown` is then *rendered* from the claims by `renderClaimsMarkdown` and is what the agent and `my_profile` read. `PUT /api/taste/memory { rejectClaim: id }` moves a claim into `rejected` and clears `rowsHash` so the next rewrite cannot be swallowed by the no-op guard; `GET` returns `claims`. A row with markdown but `claims === null` (pre-migration) still works.
- v5.2 (in progress, see SPEC.md "# v5.2 — Memory from the log"): the memory prose is rebuilt from the watched rows (`src/lib/memory/rows.ts` renders them; `rewriteMemory` returns `{ markdown, dropped }` and no-ops when the rows hash and the episode watermark are unchanged), chat and swipe episodes are the only evidence left, there is no extraction model call, `log`'s `note` is the one place a remark about a title lands and `remember` is the one place a titleless taste statement lands, and `DELETE /api/taste/log { imdbId }` removes a row with its logging episodes.
- v5 (in progress, see SPEC.md "# v5 — Simpler"): three sections (Log, Ask, You), ratings are 1–10 with states rated/want/seen/unseen, signed-in chat threads are stored server-side per user (signed-out ones are not), Tonight is computed on demand (no cron), Letterboxd imports by public-profile crawl with CSV fallback. Letterboxd blocks every paginated or sorted films/diary URL for server clients (403), so the crawl reads page one of films and of the diary, walks the whole watchlist, and takes the last 100 viewings from the RSS feed; the CSV export remains the complete path.
- v5.1 (see SPEC.md "# v5.1 — Ask polish"): scores are one-decimal end to end (`watched.score` is `real`, migration 0008; `validateScore` takes 1.0–10.0 in tenths, `isLiked` is still ≥7); the `log` tool takes `kind` ("film" | "show") and `season`, returns `{ ambiguous, candidates }` when a name has two strong candidates, and treats a title with no score and no state as `seen`; `tonight` and the pick engine take `kind`, `genre` and `unseen` (default true: nothing with any watched row); provider names are cleaned for display (`cleanProviderName`: "HBO Max Amazon Channel" → "HBO Max"); the system prompt speaks sentence case with no preamble; a stored assistant message is tidied (`tidyMessage`) into one text part per run.
