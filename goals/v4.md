# v4 goal brief — You (the log with a brain)

Source of truth: `SPEC.md` → "# v4 — You". Decisions: `grilling/2026-09-11-taste-agent.md` → "Decisions (session 4)". Standing rules in `CLAUDE.md` apply (Opus subagents at high effort, OpenRouter only, no Kevin Bacon framing, fresh UI, explicit taste signals only, `pnpm typecheck && pnpm lint && pnpm test` green before any claim).

Work one chunk at a time, in order. Each chunk ends with a commit and push to `main`, a production deploy (`vercel --prod` or the Git integration), and a one-paragraph report of what was verified in production. Do not start the next chunk until the current chunk's done-criteria are all true. Dev server on port 3100 (3000 belongs to another project).

## Chunk A — memory, log, You, Numbers

Done when:
1. Drizzle migration adds `titles` (imdb id PK, tmdb id, kind, name, year, runtime, seasons JSON with episode counts, genres, poster path, providers JSON, fetched at), `memory` (user id PK, markdown, pinned markdown, updated at) and `episodes` (id, user id, at, kind log|swipe|chat|play, title imdb id nullable, text). Applied to Neon. PGlite conformance suite covers all three in both store implementations.
2. `titles` fills lazily from TMDB on log, import and pick; a `getTitles(ids)` helper serves names, posters, runtime and genres. `/api/names` and the client poster hook read from it.
3. Log field: `/api/taste/log` accepts a title query, returns candidates (film or show; a show carries seasons) and writes a `watched` row (source "log") plus an episode with the optional line verbatim. The client component is one input at the top of You: type, pick, bucket, optional line, done in under ten seconds.
4. Memory rewrite job: after any request that adds episodes, `waitUntil` runs `rewriteMemory(userId)` on DeepSeek Flash with reasoning off; ≤40 lines; pinned lines preserved verbatim; never runs concurrently for the same user (a simple updated-at guard is enough). Unit-tested with a mocked model.
5. Chat: system prompt carries the facts summary plus the memory markdown every turn; new `recall` tool searches episodes by keyword; taste statements in a user message are extracted into episodes at the end of the turn (one cheap model call, skipped when nothing to extract). Existing taste tools keep working; `my_taste` returns the memory.
6. You page is home: memory prose with Edit (edits land in `pinned`), recently logged (10), tonight row (existing engine, expands to three picks with Play), Numbers, Services, Imports, Later, swipe button. Signed-out visitors see one sentence and Sign in.
7. Numbers: `/api/taste/numbers` returns per-month counts and hours (film vs TV), top 12 people with faces, decades, runtime finished, genres split liked/meh, and the log rows; the page renders hand-drawn SVG charts and a filterable log table. No chart library, no model call. Tested on fixture rows.
8. Typecheck, lint and tests green; production verified: log a title, see it in recently logged and in Numbers, ask the chat "what do I like" and get an answer that quotes the memory.
